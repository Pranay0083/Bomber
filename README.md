# Blast Arena

A grid-based bomb battle game in Java: you against one to three computer players, last one standing wins.
Built as a low-level design exercise, so the game rules live in a plain Java module with no graphics code,
fully unit tested, and the desktop client only sends commands in and draws the events that come out.

## Play

You need **Java 21** or newer ([Temurin](https://adoptium.net/) is a good free build).

1. Download `blast-arena-<version>.jar` (from a release, or the `blast-arena-jar` artifact of a CI run).
2. Run it:

   ```
   java -jar blast-arena-0.1.0.jar
   ```

On macOS the jar starts without `-XstartOnFirstThread`; the launcher switches GLFW to its `glfw_async` mode itself.

### Controls

| In a match | |
| --- | --- |
| Arrow keys or WASD | Move |
| Space | Drop a bomb |
| P or Esc | Pause; then R restarts the round, Q quits to the menu |
| M | Sound on or off |
| Enter | Next round, once a round is over |

In the menu, **B**, **D** and **M** choose the number of bots, their difficulty and the match length (best of 1, 3 or 5).

### Rules

- A bomb explodes after 2.5 seconds and blasts up, down, left and right. Walls stop the blast; the first crate it hits breaks.
- Fire kills anyone in it, the bomb's owner included, and sets off other bombs.
- Broken crates sometimes drop a power-up: an extra bomb, more blast range, or more speed.
- After two minutes, sudden death: walls close in from the edges. Tiles about to fall are striped red.

### Level editor

Choose **New level** in the menu, or **Edit** on a saved one. Left-click paints, right-click erases.

| Key | |
| --- | --- |
| 1 to 8 | Floor, wall, crate, spawn, crate zone (may get a crate), extra bomb, range, speed |
| B, R, F | Brush, rectangle, flood fill |
| M | Mirror every edit into all four quarters |
| Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z | Undo, redo |
| `[` `]` and `,` `.` | Width and height |
| `-` `=` | Crate density for crate zones |
| N, Cmd/Ctrl+S, T | Rename, save, test play |

Problems (a gap in the border, a trapped or unreachable spawn) are listed and outlined in red; the level can be
played once there are none. Levels are saved as JSON in `~/.blastarena/levels/`.

## Build from source

```
./gradlew build            # compile and run the tests
./gradlew :desktop:run     # play
./gradlew :desktop:dist    # the runnable jar, in desktop/build/dist/
./gradlew :core:soakTest   # 500 bot-versus-bot rounds (about a minute)
```

Useful when working on the game: `./gradlew :desktop:run --args="--start=random --autoplay --speed=5"` puts a bot
in your seat and plays a whole match by itself. See `DesktopLauncher` for the other options, including
`--screenshot=<file>` to save a frame without anyone at the keyboard.

The sprites and sounds are generated by `tools/make_sprites.py` and `tools/make_sounds.py`
(standard library Python only), so they can be changed and regenerated.

## How the code is organised

Two Gradle modules. `core` holds every game rule and depends on nothing but the JDK, SLF4J and Jackson;
it cannot import LibGDX because it does not depend on it. `desktop` is the LibGDX client.

```
core/src/main/java/com/blastarena/core/
  model/    Position, Direction, PlayerId, PlayerStats, GameConfig
  board/    Tile (Floor, SolidWall, Crate), Board, MapGenerator
  entity/   Player, Bomb, Fire, PowerUpDrop
  rules/    MovementValidator, BombPlacer, ExplosionResolver, DeathChecker, WinConditionChecker
  command/  Move, PlaceBomb and Idle commands
  control/  Controller and the read-only WorldView
  engine/   GameWorld, GameEngine, GamePhase states, Match, sudden death
  event/    GameEvent types and EventPublisher
  powerup/  PowerUp and its three kinds, PowerUpFactory
  bot/      DangerMap, PathFinder, EscapeChecker, BotController, Easy, Medium and Hard strategies
  level/    LevelData, LevelCodec, validation rules, editor commands and tools, MapSource
desktop/src/main/java/com/blastarena/desktop/
  screen/   Menu, game, editor and results screens
  render/   Board and HUD drawing, sprites, sliding animation
  audio/    Sound effects driven by game events
  input/    KeyboardController
  storage/  FileLevelRepository
```

Each tick of `GameEngine` runs in a fixed order (commands, pickups, fuses, explosions, crates, fire, deaths,
phase), and all randomness comes from the config's seed, so the same seed and inputs always replay the same game.

| Pattern | Where |
| --- | --- |
| Command | Player commands; editor edits with undo |
| Strategy | Power-ups, bot difficulties, editor tools |
| Observer | Game events feeding the animation, sound and HUD |
| State | Countdown, playing, sudden death, round over |
| Template Method | The bots' decision order: flee, attack, collect, explore, wait |
| Factory, Builder | `PowerUpFactory`, `MapGenerator`; `GameConfig.Builder` |
| Facade | `GameEngine` |
| Decorator | `MirrorTool` |
| Specification | Level validation rules |
| Repository, Adapter | `LevelRepository`; `CustomLevelSource` |
